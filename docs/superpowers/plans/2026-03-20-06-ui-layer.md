# UI Layer Cleanup — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Standardize all UI panels to a consistent lifecycle, rename `PlayerDetailPanel` to `AdminPanel`, auto-generate Give Items from the asset registry, and decouple `HudController` from the Phaser `Player` entity.

**Architecture:** All panels implement `constructor(scene)`, `show(data)`, `hide()`, `destroy()`. `HudController` reads from a plain `PlayerState` object — `GameScene` updates this object each tick. `AdminPanel` fetches the asset registry from `/api/assets` and generates rows dynamically.

**Tech Stack:** Phaser.js 3 + DOM. Existing asset registry API. No new dependencies.

**Spec:** `docs/superpowers/specs/refactor/06-ui-layer.md`

**Prerequisite:** Plan 04 (EntityManager) must be complete.

### Task 2: Standardize missing lifecycle methods

For each panel missing `show(data)`, `hide()`, or `destroy()`, add the missing methods.

- [ ] **Pattern for `hide()`** (if panel uses DOM elements):
```javascript
hide() {
  this._container.style.display = 'none';
}
```

- [ ] **Pattern for `destroy()`** (removes DOM elements to prevent memory leaks):
```javascript
destroy() {
  if (this._container && this._container.parentNode) {
    this._container.parentNode.removeChild(this._container);
  }
  this._container = null;
}
```

- [ ] **Rule for panels**: panels must not directly mutate game entities. If a panel currently calls `npc.setEmotion(...)` or `player.hp = ...`, replace with an event emit or a callback to the scene:
```javascript
// Instead of:
this.npc.setEmotion('happy');
// Do:
this.scene.events.emit('npc:setEmotion', { npc: this.npc, emotion: 'happy' });
```

- [ ] Work through each non-compliant panel from the audit, adding missing methods.

- [ ] Manual check after each panel: open panel in game, close it, reopen — no crashes, no DOM leaks.

- [ ] Commit after each panel:

### Task 4: Auto-generate Give Items from asset registry

**Files:**
- Modify: `src/ui/AdminPanel.js`

- [ ] Find current hardcoded Give Items rows:
```bash
grep -n "give\|Give\|addItem\|giveItem" src/ui/AdminPanel.js | head -30
```

- [ ] Replace hardcoded rows with a fetch from `/api/assets` on `show()`:
```javascript
async show(data) {
  this._playerData = data;
  if (!this._assetRegistry) {
    const res = await fetch('/api/assets');
    this._assetRegistry = await res.json();
    this._buildGiveItemsUI();
  }
  this._container.style.display = 'block';
}

_buildGiveItemsUI() {
  const categories = { resources: [], equipment: [], crafting: [] };

  for (const [id, asset] of Object.entries(this._assetRegistry)) {
    const category = asset.category ?? 'resources';
    if (categories[category]) categories[category].push({ id, ...asset });
  }

  this._giveItemsContainer.innerHTML = '';

  for (const [cat, items] of Object.entries(categories)) {
    const heading = document.createElement('h4');
    heading.textContent = cat;
    this._giveItemsContainer.appendChild(heading);

    for (const item of items) {
      const btn = document.createElement('button');
      btn.textContent = `Give ${item.name ?? item.id}`;
      btn.onclick = () => this._onGiveItem(item.id);
      this._giveItemsContainer.appendChild(btn);
    }
  }
}
```

- [ ] Manual check: open admin panel, Give Items shows all items grouped by category.
